# Detailed

## Purpose

Activate a deliberately high-detail mode for the relevant project scope or output.

The purpose is to make the material explicit, explanatory, and easy to understand even for a reader who has little prior context.

## Required behavior

When supplied as a tag:
- Expand descriptions and explanations substantially.
- Describe traits, structures, behaviors, relationships, and relevant mechanisms with enough context to make them clear.
- Explain how an abstract trait manifests in practical behavior when useful.
- Avoid compressed labels, unexplained shorthand, and thin one-line summaries when meaningful detail is available.
- Include relevant examples when they clarify how a character speaks, behaves, responds, or interacts.
- Preserve organization with appropriate headings and subheadings.
- Maintain relevance; do not pad with repetitive or unrelated detail.

## Tag-only activation

The special `Detailed` tag behavior activates when the user supplies `Detailed` as a tag or explicitly identifies it as a tag.

Merely using the adjective “detailed” in ordinary conversation does not automatically activate this entire tag mode.

A direct instruction such as “make this paragraph more detailed” still applies to that requested paragraph in the ordinary sense, but it does not silently activate the global Detailed tag across the project.

## Scope

Apply the tag only to the component or project scope to which it was assigned.
