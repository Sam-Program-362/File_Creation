# Context Reconstruction

## Purpose

Turn scattered, messy, abbreviated, repetitive or partially contradictory information into a coherent understanding of the user's project. Improve organization and clarity without changing the meaning or silently deciding unresolved questions.

## Activation

Use when the supplied context is fragmented across messages, notes, files, bullet lists, shorthand, screenshots, mixed timelines or unrelated-looking fragments.

## Procedure

### 1. Inventory the fragments

Identify each distinct source or fragment. Preserve names, coined terms, quoted phrases, numbers, dates, constraints and unusual wording that may carry intentional meaning. Correct obvious typographical noise only when the intended meaning is unambiguous.

### 2. Segment by information unit

Break material into meaningful units, for example:
- concept premise and intended experience;
- character identity, traits and history;
- relationships and interaction patterns;
- setting and world rules;
- chronology and events;
- plot, conflict and scenario circumstances;
- mechanics, constraints and exceptions;
- user preferences, tags and Bedrocks;
- open questions and unresolved alternatives.

These are sorting options, not a fixed output template. Create custom groups where necessary.

### 3. Resolve references and entities

Identify who or what each name, pronoun, alias and role refers to. Distinguish:
- same entity with multiple names;
- different entities with similar names;
- a title from a personal name;
- an in-world organization from its members;
- a character's belief from an objective world fact.

If identity cannot be established, retain the ambiguity instead of merging entities.

### 4. Reconstruct chronology and causality

Where time matters:
- order events by explicit dates, sequence markers or clear causal references;
- distinguish event time from the time a note was written;
- identify flashbacks, memories, alternate timelines or hypothetical events;
- distinguish “A happened before B” from “A caused B”;
- mark chronology gaps or incompatible dates.

Do not invent dates, causal links or missing events simply to create a smooth timeline.

### 5. Reconstruct relationships and state

Identify explicit relationship facts, changes over time, disagreements, shared history and interaction patterns. Separate a character's interpretation of another person from objective facts. Preserve changes rather than flattening an evolving relationship into one static label.

### 6. Reconcile duplicates and contradictions

- Merge exact duplicates without losing unique wording or qualifiers.
- Preserve repeated information when repetition signals importance or emphasis.
- If two statements can both be true in different contexts, record the scope or time distinction.
- If two claims directly conflict, retain both and mark the conflict.
- Prefer an explicit user correction over an older user statement when it is clearly a correction.
- Do not silently resolve material conflicts through plausibility alone.

### 7. Separate fact, belief, suggestion and uncertainty

Classify reconstructed units using the Evidence and Inference system. For example:
- “The queen is secretly afraid” may be an established fact if the user states it as author truth.
- “The guard believes the queen is afraid” is a character belief.
- “The guard seems suspicious” may be an interpretation from a transcript.
- “The queen might be afraid of losing control” may be a proposed inference.

Do not convert dialogue, rumor, speculation or an in-world lie into objective project truth.

### 8. Preserve the user's intent

Use concept logic to connect fragments only when the connection is strongly supported. Without Improvise, do not invent major missing context. With Improvise, fill necessary connective elements while preserving explicit facts and Bedrocks; disclose meaningful new additions in the Analysis Sheet and do not include a Missing Elements section.

### 9. Produce a reconstructed context map

Return to the Analysis Sheet coordinator:
- a concise reconstructed premise/context;
- categorized information units and their scopes;
- entity/name mappings, if relevant;
- chronology and causal links, where supported;
- relationship/event progression, where relevant;
- duplicates consolidated;
- contradictions and ambiguities preserved;
- explicit facts versus beliefs, inferences and proposals;
- any Bedrocks, tags and downstream destinations identified.

The reconstructed map is an internal analysis result unless the user explicitly requests a standalone context reconstruction document.

## Completion check

- [ ] All meaningful fragments are accounted for.
- [ ] Names and entities have not been incorrectly merged.
- [ ] Timeline and causality are only asserted when supported.
- [ ] Contradictions are preserved or resolved through explicit user correction.
- [ ] Beliefs and claims are not mislabeled as facts.
- [ ] Important qualifiers, constraints and Bedrocks remain intact.
- [ ] The reconstructed map can be used by the Analysis Sheet coordinator without reopening the entire raw context unnecessarily.
