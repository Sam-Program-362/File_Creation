# Lorebook Planning — Content Pattern Selection

The following patterns come from the supplied Lorebook Creator reference. They are reusable design patterns, not mandatory boilerplate. Select them only when the project needs them.

## Anti-soft / anti-default

Use when generic model defaults would distort the established character or scene. The eventual entry should:
- state the core directive immediately;
- name the concrete forbidden defaults;
- state the positive behavior that should replace them;
- explain how the behavior remains consistent with the actual character.

Avoid vague instructions such as “do not be generic.” Identify the precise failure mode.

## Personality filters

Use when the same scene or dynamic should be expressed differently according to the character's personality. The source pattern includes reserved / cold / composed, arrogant / superior, dominant, and quiet-intensity filters. Adapt these to the actual project's characters and do not paste generic types that do not apply.

## Non-escalation

Use when an action or moment must not automatically become a more intense action, confession, or resolution. State what may continue, stop, or change, and keep the decision dependent on the established character and current dynamic.

## Time continuity

Use only when time continuity matters. Preserve the established time of day; do not force a clock change or imply elapsed time without a concrete reason.

## Dominance preservation

Use only when the project establishes a power or dominance dynamic. Define who holds which kind of control and what does or does not constitute a shift. Do not impose dominance assumptions on unrelated projects.

## Progression mandate

Use when narrative momentum is an explicit design requirement. The eventual entry may require a concrete progression such as a physical change, power shift, environmental development, consequence, or temporal movement. Avoid loops that repeat the same frame without change.

## Aftercare / aftermath matched to personality

Use when the project includes an aftermath phase and character fidelity requires it. Do not force tenderness, cuddling, emotional openness, or any other behavior inconsistent with the defined character.

## Content density and practical specificity

The supplied Lorebook Creator favors dense, structured, actionable content over vague advice. It recommends clear uppercase titles, an immediate directive, concrete behavioral and psychological rules, explicit forbidden behavior, personality filters, and progression / continuity guidance where relevant. The planner should tell the downstream creator which of these are needed for each entry.

The source also emphasizes character fidelity, narrative momentum, practical rather than purple-prose instruction, directness for sexual / power / dark subject matter where appropriate, and first-class treatment of male and futanari context when relevant. Preserve relevant project-specific requirements without inserting specialized material into projects that do not call for it.

## Pattern selection check

For each selected pattern, answer:
- What concrete project need justifies it?
- Which character, relationship, world, or scene does it apply to?
- What would go wrong without it?
- What is the intended positive behavior?
- Which Bedrocks or approved facts constrain it?
- How will a test demonstrate that the pattern works?

If those questions cannot be answered from the project, omit the pattern rather than using it as filler.
